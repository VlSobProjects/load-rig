# Session note

## Type

`documentation`

## Goal

Answer the three questions the SUT project raised while it joined the shared desk, and write what
they change into this project's desk rules.

## Completion criteria

1. Each question carries a decision with its reason and the alternative it was weighed against.
2. What the decisions change is in `docs/processes/exchange-desk.md`, and nowhere else is left
   saying the opposite.
3. Every project on the desk is told, by a letter of its own written as a draft.

## Scope boundaries

The seven rules already in force are not reworded. The letter that opened the desk is not edited
and not replaced. No rule of another project is touched: each adopts the amendments in its own
place.

## Status

`completed`

## Result

All three criteria are met. The questions reached this project through the user, before the SUT
project's answer to `EX-1` was written; the decisions went back on the desk as `EX-2`.

**A letter has one addressee, as an eighth rule.** `EX-1` was addressed to five projects and
carried one `What it changed`: until the last of them answered it could not be marked answered, and
the count a session may give its user was wrong for every project that had already done its part.

**A letter that changes nothing lands too, as an addition to the first rule.** A notice or a
reference that changes nothing left its field empty for good and stayed among the letters that
wait. The recipient now writes that it changes nothing, with the one reason and the date.

**The desk stays closed to the public.** A public repository cites letters its reader cannot open,
and that is accepted.

Five letters went on the desk as drafts, `EX-2` to `EX-6`, one to each of the other projects and
all with the same text, which is the eighth rule applied for the first time.

## Decisions

- **One letter per addressee, rather than one line per addressee.** The SUT project offered both.
  A line for each project in `What it changed` mends one of the three things several addressees
  break and leaves the status and the answer as they were; and the view of what waits cannot ask
  whether a field lacks a project's name. The price is that what goes to several projects is
  written, and if need be corrected, once for each.
- **`EX-1` stays the one exception.** A sent letter is not edited, and replacing the letter two
  projects had already acted on would cost more than the exception does. A project that has
  answered it no longer counts it.
- **Nothing, with a reason, rather than hiding notices from the view.** Hiding the two kinds of
  letter that ask for no answer would lose the only mark that one was read. The reason is asked
  for instead of the place it was read in, because it is what a later reader needs: this is how
  the rename notice of 2026-09-03 was recorded on the old desk.
- **Not opened to the public.** The desk holds projects that are not public, and the rule that a
  letter carries nothing every project may not read sets a lower bar than that anyone may read it.
  Nothing is lost against the folders the desk replaced, which no public reader could open either.
